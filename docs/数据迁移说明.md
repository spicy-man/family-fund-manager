# 旧版本数据迁移

新版压缩包不会包含本地账目数据。升级后，需要把旧版本根目录下的 `data` 和 `backups` 文件夹复制到新版本根目录。

## 迁移步骤

1. 先关闭旧版和新版程序，确认运行窗口已经退出。
2. 解压新版程序到一个新的文件夹，不要直接覆盖旧版本。
3. 在旧版本根目录找到以下两个文件夹：
   - `data`：当前账目、成员、标的配置和独立结算账本，必须复制整个目录，不能只复制 `db.json`。
   - `backups`：系统自动生成的历史账目备份。
4. 将旧版本的整个 `data` 文件夹复制到新版本根目录。
5. 将旧版本的整个 `backups` 文件夹复制到新版本根目录。
6. 如果系统询问是否合并或替换文件：
   - `data` 应以旧版本文件为准，覆盖新版自动生成的空数据文件。
   - `backups` 可以合并；遇到同名文件时保留旧版本文件即可。
7. 双击新版的 `start.bat`，进入系统后检查成员、历史账目、余额和标的配置是否完整。

首次启动时，如果旧版 `db.json` 内仍包含指数历史缓存，系统会自动将其迁移到独立的 `data/index-cache.json`。该文件只保存可重新获取的市场数据，不属于三文件核心账本快照。

如果 `index-cache.json` 中存在早期 v3.13.0 写入的自定义标的行情，系统会先安全写入 `data/custom-benchmark-cache.json`，再从指数缓存中移除对应字段；迁移可以中断重试，不影响账本。

迁移完成后的目录应类似：

```text
基金账目管理系统/
├─ backups/
│  ├─ db_backup_*.json            # 旧版账目备份，可继续保留
│  └─ snapshot_backup_*.zip       # 新版三文件完整快照
├─ data/
│  ├─ db.json
│  ├─ config.json
│  ├─ index-cache.json
│  ├─ custom-benchmark-cache.json
│  ├─ ticker-cache.json
│  └─ settlements.json
├─ public/
├─ server.js
└─ start.bat
```

## 注意事项

- 迁移前不要删除旧版本，确认新版数据正常后再自行归档旧目录。
- 不要在程序运行时复制、覆盖或删除 `data` 内的任何核心文件，否则系统会拒绝读取不完整的账本。
- 不需要复制旧版的 `node_modules`；新版首次启动时会自动安装依赖。
- 如果迁移后显示的是空账本，请再次确认旧版的 `data/db.json` 已复制到新版根目录的 `data/db.json`，并重新启动程序。
- 若旧版本设置过 `FUND_DATA_DIR` 或 `FUND_BACKUP_DIR` 环境变量，实际数据可能不在项目根目录，请从变量指向的目录迁移。
