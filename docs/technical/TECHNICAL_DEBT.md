## 当前技术债

### TD-002：批次收费处置仍随处置数和活动批次数相乘增长（P2，已监控）

关联任务：TASK-013（预算建设已完成，渐进复杂度仍然存在）。

当前实现已消除请求内重复重放，并把每次处置压缩为“聚合一次、应用一次”；但为了逐批门槛和审计明细，每次收费处置仍需扫描全部活动批次。

现已为生产使用的完整逐批审计重放建立典型、家庭账本建议上限和 10,000 事件导入上限三档预算，达到耗时预算 80% 时报警。只有真实账本接近阈值时，才评估批次安全合并、检查点或增量重放；任何方案仍须保留逐批审计明细、历史费率版本和完整重放等价验证。

### TD-003：安全模型仅适用于回环地址上的单用户部署（P2）

关联任务：TASK-008。

服务默认只监听 `127.0.0.1`，因此不是局域网直接可访问服务；但当前没有身份认证，也未按网络服务标准实现 CSRF、Host/Origin 校验和频率限制。

约束：不得通过监听地址修改、端口转发或反向代理直接扩大暴露范围。任何此类变更必须先完成安全方案。

### TD-005：前端页面和协调层仍偏单体（P3）

关联任务：TASK-010。

`public/index.html` 仍承载全部页面 DOM，部分前端控制器继续依赖全局状态和 DOM 查询。当前规模可维护，但功能继续增长时会提高联动修改成本。

### TD-006：测试运行体验与可观测性有限（P3）

关联任务：TASK-011。

测试质量较高，但仍通过 `package.json` 串联独立 Node 脚本；缺少统一筛选、覆盖率、watch、请求 ID、日志级别和结构化错误上下文。
