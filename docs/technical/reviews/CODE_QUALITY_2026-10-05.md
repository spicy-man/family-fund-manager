# v4.0.1 代码质量判断与渐进重构建议

评估日期：2026-10-05。范围：当前工作区 v4.0.1 的核心计算、存储、路由、前端协调层、演示沙盒及测试组织。本文是维护性评估，不是全量缺陷审计，也不构成财务正确性认证；未检查用户正式账本。

## 判断

项目不属于典型的“屎山代码”，但已有明显技术债。适合继续维护，并安排有边界的局部重构；没有足够依据支持推倒重写。

判断依据是职责边界、修改联动成本、数据保护和回归能力，文件行数仅用于定位维护热点。对于本地家庭基金账本，原生 JavaScript、Express 和 JSON 存储仍是合理选择，不应仅为采用新技术而迁移框架或数据库。

## 已有基础

- 核心计算、结算算法、批次处置、费率策略和事件排序已经分离成模块。
- 存储具备临时文件原子替换、多文件恢复日志、写入前备份和账本目录独占锁，说明项目已经考虑写入失败和异常退出。
- 测试覆盖历史余额不足、算法版本兼容、高水位、存储回滚、导入校验、重复提交和异步竞态，具有实际回归价值。
- 浏览器演示沙盒复用核心计算及 API 路由，避免维护两套独立业务规则。

## 建议执行顺序与验收

这些是待处理建议，尚未实施。状态与排期统一维护在 [TASKS.md](../../project/TASKS.md)。

1. **收缩前端总控（TASK-010）**：优先迁出成员编辑、流水编辑/延迟删除和提示消息，把 `app.js` 留作装配与状态协调。验收覆盖成员增删改与 GP 设置、流水编辑、三秒撤销删除、提交后刷新及失败恢复；本地版与沙盒均验证。
2. **抽取交易业务服务（TASK-015）**：将候选账本构造、重放校验和成功后的保存流程移出 HTTP 回调。不要把不同事件规则强行合成通用处理器。验收保持请求/响应契约、错误分类、锁账规则、历史余额校验、全额退出金额、人民币台账及事件顺序号一致；保留当前单次校验重放约束。
3. **拆分服务入口（TASK-016）**：分离账本读取/迁移/状态缓存和行情同步，明确依赖与生命周期。验收覆盖启动、异常退出恢复、目录独占、缓存失效、关闭清理及 `FUND_EXTERNAL_SYNC=0` 隔离行为。
4. **整理存储边界（TASK-017）**：分离核心账本与可重建缓存，并评估显式初始化接口。验收确保取得目录锁后才能恢复或读写账本；写入前备份、快照回滚、失败关闭和锁释放行为保持一致。
5. **拆分计算与输出职责（TASK-018）**：最后处理计算器，先建立重构前后差分验证，再逐步分离基准对比和展示输出。验收覆盖 v1/v2/v3 结算、历史处置版本、批次、份额、净值、业绩报酬及美元/人民币结果一致，并继续满足重放性能预算。

每次处理一个职责，提交应可独立审查、回退。完成标准是边界清晰、联动减少且行为保持一致，不是文件低于某个行数。财务计算语义、历史算法版本与快照不得随整理代码改变。不要在同一轮混入框架迁移、数据库迁移或财务规则调整。

## 测试补强（TASK-011）

- 为成员管理、流水编辑/撤销删除、结算预览确认和 ZIP 恢复补充关键浏览器交互验证；优先覆盖真实风险，不为每个拆出的函数添加实现镜像测试。
- 保留隔离临时账本和关闭外部同步的测试约束。
- 改善失败定位与单文件执行体验；是否引入测试运行器、覆盖率或 watch 模式，按实际收益评估。
