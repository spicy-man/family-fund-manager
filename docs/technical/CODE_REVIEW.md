## 核心技术亮点

### 1. 忠实于价值投资哲学的合伙契约
系统不是简易的流水账本，而是把巴菲特合伙契约转化为严格的代码约束：
- 零固定管理费，只有收益超过 6% 年化复利门槛后才计提 25% 提成。
- 逐批次（Lot）独立跟踪持有天数与高水位（HWM），高水位 NAV 只升不降。
- 报酬结算通过份额划转实现，不直接稀释基金单位净值，实现了 GP 与 LP 利益的极致绑定。

### 2. 确定性事件溯源与多版本重放引擎
`lib/calculator.js` 采用纯函数式事件重放设计：
- 完整重现资金演化全历程，拒绝就地 CRUD 造成的历史状态丢失。
- 针对历史迭代中产生的 v1（汇总收费）、v2（逐批累计）、v3（分期高水位）规则，引入版本标识与锁定快照比对机制，确保历史报表无论系统升级多少次均保持 100% 字节级确定性。

### 3. 数据层 WAL 事务机制与崩溃防御
`lib/storage.js` 实现了超越普通 JSON 存储的防御能力：
- 每次写操作前自动创建 `.snapshot-transaction.json`。
- 服务启动时自动检测 `recoverInterruptedSnapshot`，若上次操作因断电异常终止，自动无损回滚。
- 核心数据操作前自动执行 `writeCoreBackup` 归档滚动 ZIP。

### 4. 稳健的逐日行情事实库与离线自治
- `v3.15.0` 引入的 `market-history.json` 实现了“只增不漏”的日线事实存储，解决了 Yahoo Finance 上游接口偶发丢日的边界问题。
- 图表库 Chart.js、拖拽库 SortableJS、字体资源全部内置，完全摆脱对 CDN 的依赖，真正做到“哪怕断网十载，系统依然如初”。

## 持续演进空间与扣分点分析（面向未来）

虽然系统在当前定位下已近乎无懈可击，但根据 `docs/technical/TECHNICAL_DEBT.md` 追踪的长期债务，仍有以下值得未来关注的工程边界：

### 1. 局域网多设备协同与只读查账需求（TD-003）
- **现状分析**：系统安全模型完全依托于 `127.0.0.1` 回环地址。由于无鉴权机制，若家庭成员希望使用手机浏览器查看个人收益，无法安全开放局域网监听（`0.0.0.0`）。
- **优化建议**：可引入轻量级、可选的“只读访问 Token / 成员口令”模式，在不增加重型 OAuth 的前提下，允许在局域网内向非 GP 成员开放个人账目只读视图。

### 2. 前端单体 HTML 结构与视图组件化（TD-005）
- **现状分析**：`public/index.html` 承载了所有看板、弹窗与表单的全部静态 DOM，前端脚本重度依赖全局 DOM 查询。
- **优化建议**：在维持“无打包编译工具（No-Build）”优势的前提下，可探索原生模板字符串或 Web Components，将各模块弹窗与卡片改为按需挂载。

### 3. 测试套件运行体验（TD-006）
- **现状分析**：`package.json` 中的测试脚本由 28 个 `node test/xxx.js &&` 串联。单次执行完整回归需 20-30 秒，且缺乏单文件快速过滤、结构化错误报告与覆盖率度量。
- **优化建议**：可编写轻量原生运行器（如 `test/run-all.js`），支持自动发现、并行执行无副作用测试与汇总统计。

### 4. 逐批处置计算的二次方渐进复杂度（TD-002）
- **现状分析**：每次出金和转让需遍历全部活动批次，复杂度为 $O(处置数 \times 活动批次数)$。
- **现状评估**：当前性能预算监控表现健康（家庭上限 231 事件耗时 2.3s，仅占预算 29%）。未来若账本持续积累数十年、事件超万条时，可评估引入安全批次合并或快照检查点。
